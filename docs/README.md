# Meal & Offer Photos — Seeder Wiring

This package wires real photos into the `pictures` table for every meal and
offer generated by `MealSeeder` and `OfferSeeder`. It does **not** contain
real photos — see below for why, and `PHOTO_MANIFEST.md` for exactly what to
source and where to put it.

## What's in here

```text
database/migrations/2025_06_03_000000_add_picture_id_to_offers_table.php
database/seeders/MealSeeder.php     (updated)
database/seeders/OfferSeeder.php    (updated)
PHOTO_MANIFEST.md                   (filename + search phrase per item)
placeholders/meals/*.png            (18 stand-in illustrations)
placeholders/offers/*.png           (4 stand-in illustrations)
```

## Why no real photos are bundled

This was generated in a sandboxed environment with no photo-generation model
and no open internet access (network is locked to code package registries
only — npm/pip/GitHub, nothing like a stock-photo site or image API). So
real photography couldn't be produced or downloaded here. `PHOTO_MANIFEST.md`
gives you the exact filename and a ready search phrase for each of the 18
meals and 4 offers so you can pull real photos from Unsplash/Pexels/Pixabay
(or generate them with an AI image tool) in a few minutes.

## What the placeholders/ folder is for

18 + 4 flat-illustration PNGs, one per meal/offer, matching the exact
filenames the seeder expects. They are **not real photos** — they're stand-in
graphics so `php artisan db:seed` gives every row a working `picture_id` and
your app doesn't break with empty images while you source real ones. Copy
them into `storage/app/public/meals/` and `storage/app/public/offers/` if you
want that now; delete/replace them with real photos later using the exact
same filenames and re-run the seeder — `updateOrCreate` means it will pick up
the new file without any code changes.

## Setup

1. Copy `database/migrations/...add_picture_id_to_offers_table.php` into your
   project's `database/migrations/` and run `php artisan migrate`.
   (`meals.picture_id` already existed; `offers` did not have one.)
2. Replace your `database/seeders/MealSeeder.php` and
   `database/seeders/OfferSeeder.php` with the versions here.
3. Add a `picture()` relation to `App\Models\Offer` mirroring whatever
   `App\Models\Meal::picture()` already does, e.g.:
   ```php
   public function picture(): BelongsTo
   {
       return $this->belongsTo(Picture::class);
   }
   ```
4. Put photos (real or placeholder) in `storage/app/public/meals/` and
   `storage/app/public/offers/` using the filenames in `PHOTO_MANIFEST.md`,
   then run `php artisan storage:link` once if you haven't already.
5. `php artisan migrate:fresh --seed` (or `php artisan db:seed` on an
   existing database — the seeders use `updateOrCreate`, so re-running is
   safe and will backfill `picture_id` on existing rows).

## How the resolution logic works

Both seeders now check `storage/app/public/{meals|offers}/<slug>.<ext>` for
`jpg`, `jpeg`, `png`, `webp` in that order. First match creates/updates a row
in `pictures` (`path`, `name`) and sets it as the meal's/offer's `picture_id`.
If nothing matches, `picture_id` stays `null` and the seeder prints a
one-line warning per missing item at the end of the run — so you always know
exactly what's left, instead of a silent gap.
