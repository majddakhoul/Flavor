Login — Token Issuance

← Back to README

How a mobile or Postman client exchanges credentials for a Sanctum bearer token. The API never touches the session guard used by the web app.

Component Active call (activation bar)
Maps to
  • Api\Auth\LoginController::store(), AuthService::verifyCredentials() (added in this rebuild specifically so the API never calls the session-bound Auth::attempt()).
  • The token is a Sanctum personal access token, stored hashed in personal_access_tokens; the client keeps the plain-text value and sends it as Authorization: Bearer <token> from then on.
  • A disabled account (status = false) is rejected here with 403 before a token is ever issued.
