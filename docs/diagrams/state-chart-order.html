Order Status — State Chart

← Back to README

Every Order carries an OrderStatus. App\Enums\OrderStatus::transitions() is the single source of truth for which moves are legal; OrderService::transition() checks it before writing, and an illegal move raises InvalidStateTransitionException instead of silently succeeding.

Open / in progress Terminal — success Terminal — cancelled
Rules encoded in the enum
  • Pending → Confirmed / Cancelled, Confirmed → Completed / Cancelled. Completed and Cancelled are terminal — no further transition is allowed from either.
  • Cancelling a Pending or Confirmed order restores the stock that checkout consumed (OrderService::cancel()).
  • Every transition fires OrderStatusChanged, which notifies the customer by mail and in-app notification — see the Order Status Update sequence diagram.
  • Cancelled orders are soft-deleted; a manager can restore one, which re-consumes stock if it is still available.
