Use Cases — Guest & Customer

Everything a visitor and a signed-in customer can do, end to end from browsing to a completed order or reservation.

Actor Use case (Flavor capability)
Where each use case lives in the code
  • Browse menu & offers — Api\Catalog\MealController, OfferController (no token required).
  • Register & verify — AuthService::register() + verify(); a Customer profile is created in the same transaction as the User.
  • Manage cart / Checkout — CartService, CheckoutService::place(); checkout locks ingredient stock and writes the order atomically.
  • Check availability & book — TableAvailabilityService::availableBetween(), then ReservationService::create().
  • Read notifications — every use case above that changes state (checkout, order status, reservation status) feeds this one automatically through the event/notification system.
