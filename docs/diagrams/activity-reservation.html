Reservation Booking

← Back to README

Booking a table, whether the customer does it themselves or a waiter takes it over the phone — the same service, the same conflict check, either way.

Swimlane (actor / layer) Decision Note
Maps to
  • App\Services\Reservations\TableAvailabilityService::availableBetween() and ReservationService::create().
  • Double-booking protection: conflictingTableIds() locks the candidate table rows with lockForUpdate() before confirming, so two concurrent bookings cannot both claim the same table.
  • App\Events\ReservationCreated → SendReservationTicket (customer) and NotifyStaffOfNewReservation (staff with the floor ability).
  • API: GET /account/reservations/availability, POST /account/reservations (customer) or POST /manage/reservations (staff, same service underneath).
