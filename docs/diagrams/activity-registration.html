Registration & Email Verification

← Back to README

The full path from an anonymous visitor to a verified customer able to order and book, spanning the guest, AuthService and the notification system.

Swimlane (actor / layer) Decision Note
Maps to
  • App\Services\People\AuthService::register() and ::verify().
  • App\Events\VerificationCodeIssued → SendVerificationCode listener → VerificationCodeMail.
  • API: POST /auth/register, POST /auth/verify-email, POST /auth/resend-verification.
  • The code is never stored as an in-app notification (see docs/NOTIFICATIONS.md) — only mailed, and held server-side in the cache with a 15 minute expiry.
